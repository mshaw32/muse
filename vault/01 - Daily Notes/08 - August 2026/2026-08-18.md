## Session 1 — Phase 4.1: Real Azure AI Foundry Voice Integration

### Context

User asked to implement `docs/PHASE-4.1-FOUNDRY-VOICE-LIVE-BUILD-SPEC.md` in full: turn Phase 4's mock voice layer into a genuinely working voice pipeline — MUSE should actually hear the user's real microphone input and actually speak back through real Azure-synthesized audio, played on real speakers. Explicit constraints: preserve the entire existing architecture (Electron shell, UI, Visualizer, Conversation/Memory/Copilot systems, existing `SpeechToTextEngine`/`TextToSpeechEngine` interfaces), and authenticate using only the currently signed-in Azure identity — no app registrations, client secrets, or service principals of any kind.

### What Got Done

**Research & validation (before writing code):**
- Confirmed `az login` session is active (`948471@cognizant.com`), and that the target subscription/resource group/Cognitive Services account named in `docs/azure-resources.md` (`mbgsol-muse-dev-resource`, kind `AIServices`, region `eastus2`) genuinely exists and is reachable.
- Proved out AAD-token-based Speech authentication end-to-end via raw `curl` *before* writing any TypeScript: discovered that token-based (non-API-key) auth against Azure Speech **requires the resource's custom-subdomain endpoint** (`https://mbgsol-muse-dev-resource.cognitiveservices.azure.com/sts/v1.0/issuetoken`), not the shared regional endpoint — the regional endpoint returns an explicit 400 telling you to use a custom subdomain. Successfully fetched a Speech token this way using an `az account get-access-token --resource https://cognitiveservices.azure.com` token.
- Attempted `brew install sox` to get native Node microphone capture (via the `mic` npm package) — blocked by GitHub Container Registry 403s in this environment (a sandbox/network restriction, not fixable by retrying). **Architectural decision**: since Node can't reliably do real, non-headless mic capture without `sox`/native bindings here, real microphone capture happens in the **Electron renderer** via genuine `getUserMedia` (real OS mic access through Chromium), streamed to the backend as base64 PCM over HTTP, which feeds a real Azure Speech SDK push-audio-stream recognizer server-side. TTS remains a simple server-side request/response (no mic dependency), so it didn't need this workaround.

**New `services/src/voice/foundry/` module (all additive — no existing exports changed):**
- `FoundryTokenProvider.ts` — Entra ID auth via `DefaultAzureCredential` (preferred) → `AzureCliCredential` fallback; token caching with expiry buffer; scope `https://cognitiveservices.azure.com/.default`.
- `FoundryVoiceConfiguration.ts` — resolves endpoint/region/model/voice from env vars with `docs/azure-resources.md`-mirrored fallbacks; resolves `VOICE_PROVIDER` (defaults to `mock`).
- `FoundryVoiceLiveClient.ts` — connection state machine; builds `SpeechConfig.fromEndpoint()` with an authorization token (never a subscription key).
- `FoundrySpeechToText.ts` — implements the existing `SpeechToTextEngine` interface exactly; real push-audio-stream recognition; exposes `feedAudio()` for the backend to push real mic bytes into.
- `FoundryTextToSpeech.ts` — implements the existing `TextToSpeechEngine` interface exactly; builds SSML, synthesizes real audio via `SpeechSynthesizer`, returns base64 MP3, maps MUSE's mock voice-profile IDs onto real Azure neural voices.
- `VoiceDiagnostics.ts` — implements `testAuthentication()`, `testConnectivity()`, `testSpeechToText()`, `testTextToSpeech()`, and `runAll()`.
- `FoundryVoiceLogger.ts`, `index.ts` — structured logging + barrel export.

**Provider switching wired into existing services (no breaking changes):**
- `services/src/voice/VoiceConfiguration.ts` — recognizes `VOICE_PROVIDER=mock|foundry`.
- `services/src/voice/VoiceService.ts` — now provider-aware; selects mock vs. Foundry STT/TTS engines based on configuration; `stt`/`tts` constructor args made optional (backward compatible with all existing call sites); added `isFoundryProvider()`/`feedAudio()`.
- `backend/src/services/voice/AzureVoiceService.ts` — added `feedAudio()`, `getFoundryStatus()`, `runDiagnostics()`.
- `backend/src/routes/voice.ts` — `/status` enriched with provider/connection/auth/model/voice fields; new `POST /audio` (feeds real mic PCM into the active session) and `GET /diagnostics` routes.

**Real audio in the frontend:**
- `frontend/src/services/voice/MicrophoneCapture.ts` — real `getUserMedia` capture, downsampled to 16kHz/16-bit/mono PCM via `ScriptProcessorNode`, base64-encoded and streamed to the backend.
- `frontend/src/services/voice/AudioPlayback.ts` — real `<audio>` element playback of synthesized speech, with `setSinkId` speaker routing.
- `frontend/src/store/voiceStore.ts` — `startListening`/`stopListening`/`speak` now drive real mic capture and real audio playback around the existing backend session calls.
- `frontend/src/components/VoiceStatus.tsx` (+ CSS) — new "Azure AI Foundry" badge showing live connection state; `frontend/src/hooks/useVoice.ts` and `VoicePanel.tsx` extended to surface `provider`/`connectionState`/`authenticationMode`.
- `electron/src/main.ts` — added a `session.setPermissionRequestHandler` so Electron auto-grants `media` (microphone) permission requests, required for `getUserMedia` to succeed in the renderer.
